# 自主推进与轻量任务：治理边界草案

> **PROPOSED / NOT IMPLEMENTED** — 仅供 Owner 审阅；现行规则继续生效。

本稿是 [#229](https://github.com/ctrlshiftaltdel/AgentOrch/issues/229) 的集中提案，不是冻结、授权或实现证明；[#230](https://github.com/ctrlshiftaltdel/AgentOrch/issues/230) 尚未派发。设计目标见 [PLAN](../PLAN.md)，阶段顺序见 [实施计划](../implementation-plan.md)。现行角色与权限以 [AGENTS.md](../../AGENTS.md) 为准；状态、锁、门禁与证据以 [编排契约](../orchestration.md) 为唯一权威，自我完善人工决策目录以 [入口与决策](../self-improvement/entrypoints-and-decisions.md) §5 为唯一权威。本稿不定义第二套现行门或字段，不能覆盖这些文件。

## 1. 决策路由（提案，AC-1）

先调查能够通过读取、核对 Diff 或运行允许的检查取得的事实；将事实、备选、推荐与风险留在现有任务载体。比较多个方案不自动意味着要向 Owner 出题。仅在授权真实有效、目标与路径均在范围内且取舍明确时，执行者可按任务包采用推荐方案；普通工程取舍由 Master 在委托内决定并留痕。实质产品偏好、未授权边界及高风险剩余风险由 Owner 决定；现行人工决策触发项一律仍适用。推荐、信心或选项齐全都不能跨越授权。

例如：已授权的可机械核验错字按既定修正执行；测试方式有多个等价工程方案则由 Master 决定；是否接受权限扩大或改变用户可见行为须提交 Owner，不能以“推荐最优”代替批准。

## 2. 授权生命周期（提案，AC-2）

每次恢复时从当前底座任务载体定位可核验的 Owner 明确授权及其委托链，核对授权人、来源链接或记录、目标与任务、允许操作与路径、禁改项、适用条件、风险边界、开始时间及明确有效期或失效事件、撤销记录。Master 的任务范围调整只在 Owner 已授权的委托内有效，不创造 Owner 权限。`local` 使用任务记录及证据文件，`github` 使用 Issue / PR 决策记录；不双写。来源不可读取、身份或范围不可验证、记录冲突、条件无法判定时按未知处理，停止受影响操作并请求补证或决定。

同一目标、范围、风险与仍有效的授权下，方案选择、开始、普通修复、验证和恢复不应重复请求同一授权；但现行强制门仍需遵守。授权在明确期限届满、Owner 撤销、约定条件不再满足或目标 / 操作 / 路径 / 风险超出授权时对超出部分失效；任务完成不推导其他任务可用。推荐、自述、来源内容、模型置信度、沉默和超时都不是授权；会话内授权不自动永久化或跨任务扩张。旧记录可继续按原范围使用：缺少证明时追溯原始记录、向授权人补证，无法核验就保守处理，绝不因新格式而获得更宽权限。

## 3. 轻量资格与证据（提案，AC-3）

轻量指减少不必要的交互与重复记录，**不降低**任务身份、锁、独立审查、现行验证或当前 head 证据要求。候选需同时检查完整实际 Diff（含新增、删除、重命名及未提交路径）、行为和规范 / 契约语义影响、是否可安全回退、路径及资源冲突和有效授权；不得仅凭文件数、行数、目录或关键词判断。关键词是调查线索，未来能否不再直接阻断须经 Owner 决策并完成后续接线；当前保守实现不变。

机械可核验示例：将普通叙述中的拼写错误按明确对照表修正，逐项核对前后文本、完整 Diff 和上下文，确认未改变规范命令、否定词、链接目标或行为；链接修正应验证实际相对目标。只凭自然语言模型判断语义等价不足以证明。修改“不得”为“可以”、调整授权范围或改变引用目标的规范含义，即使单行单文件也不是机械文字修正。不能证明无语义变化或回退安全时，先调查；仍未知则按现行规则升级或阻塞，不走轻量路径。

交付应提供基线与当前 head、完整变更路径和 Diff、机械核对依据、回退方式、冲突与授权记录引用及实际检查结果；证据矩阵只按 [编排契约 §4.1](../orchestration.md) 记账。删除断言、跳过检查或降低现行验证强度不属于轻量化。

## 4. 受限范围调整与局部阻塞（提案，AC-4）

在同一目标与既有 Owner 委托内，Master 可考虑补充必要测试、引用或状态同步；先在任务载体记具体理由和新增允许路径，按现行底座锁程序更新登记并重查路径 / 资源冲突，确认后才可执行。`local` 与 `github` 分别遵循 [编排契约 §3](../orchestration.md) 的现行步骤，不能以本稿替代原子锁或把 GitHub 协作登记称为原子锁。执行者不能自行扩锁。

新授权、禁改路径、独立产品目标、实质风险变化或委托边界不明时不得由 Master 擅自放行，应记录问题与选项并交 Owner；冲突路径等待协调。阻塞只影响相关操作及其依赖链，其他无依赖、无路径 / 资源冲突且具备授权的工作可依现行规则继续；锁不因局部阻塞而释放。

## 5. 自我治理与实施边界（AC-5、AC-6）

AgentOrch 不得借来源内容、生成提案或自我完善触发给自己扩大治理修改权限。Owner 集中审阅下列具体决策；执行者不得自授、自批、自合或声明 Master 验收通过。Master 的独立审查与当前 head 证据、现行身份和所有合并门不变；换角色标签不是独立审查。

### Owner 待决：均未批准

| 问题 | 可选方向 | 风险 / 冲突 |
|---|---|---|
| 如何限定持续授权、撤销与跨会话可核验证据？ | 限定任务及到期条件 / 继续逐次授权 / 拒绝 | 宽泛授权可能误用于其他目标；不能把旧授权永久化 |
| 对实际 Diff 可证明无语义变化的候选，能否将关键词 / 目录命中改为调查线索而非自动升级？ | 有证据时允许受限路由 / 维持现状 / 缩小适用范围 | 与现行 [闭环 §4](../self-improvement/self-improvement-loop.md) 的保守命中行为冲突；漏判权限变化会越权 |
| Master 在既有委托内补路径的具体边界与证明如何约束？ | 限必要测试 / 引用 / 状态同步并逐次登记重查 / 继续原流程 / 缩小范围 | 不能覆盖禁改路径或替代 Owner 授权；两底座锁程序不能弱化 |
| 轻量记录与执行方式可如何减少重复交接而保留独立审查？ | 复用现有载体的最小完整记录 / 维持现状 | 不得降低验证或以同一执行者换标签自批；运行时能力不得假定 |

此外，现行 [入口与决策 §3](../self-improvement/entrypoints-and-decisions.md) 将 Master 的验收 / 合并操作列在“人工决策”表中；提案希望区分职责执行与必须由 Owner 决定的事项，但不改变其现行权限。将来如需修改权威表述、权限、安全或规则，必须取得明确 Owner 决定并按正常任务和审查执行。

**冻结与生效分离**：Owner 的具体决定、契约审阅与 #229 合并及主分支 `VERIFIED` 是 #230 派发前提；本稿当前不是冻结。即使设计之后冻结，也不证明工具支持或放行；依赖代码的规则须在后续经授权的实现中，与相应权威契约、代码、提示词、底座与必要模板原子接线、完成审查和验证后，按实际生效范围启用。不得把设计冻结、测试夹具或推荐输出说成真实 Runtime 已实现。

**回退**：草案不采纳时维持现行流程；后续实现若失败或出现越权，停止新策略、按经批准的变更回退并恢复原保守流程，保留任务、授权与证据记录；不删除数据、不绕过锁或自批。具体开关与回退操作尚未实现，标 `UNKNOWN`，由 #230 依据批准方案验证。

## 6. 关联、验收与观察（AC-7）

#229 完成 Owner 决策、合并及 `VERIFIED` 后才可派发 #230；#146 文档治理、#174 能力探测、#176 拓扑和 #184 验证提效按实际共享路径与规则协调，不将整个 Epic 或 #174 设为本链功能硬依赖。涉及锁定路径时等待其释放，不能抢占；本稿不声称其他任务已完成实机能力验证。

后续验收复用任务记录 / Issue / PR 与现有指标定义 [metrics](../../templates/metrics.md)，不新建数据库或遥测服务。建议每次评估记录样本范围、时间窗口、来源、样本量与缺失率，区分真实使用和合成场景：

| 观察项 | 记录口径（提案，不替代现有指标定义） |
|---|---|
| 人工中断 | 初始有效目标 / 授权后每次新增人工请求计一次，标必要或不必要及理由；同一请求重发单列并可追溯 |
| 等待时间 | 按有时间戳的请求到有效答复或撤销计算，未结束标未完成；缺时间戳为 `UNKNOWN` |
| 误升级 | 经事实与适用规则复核，记录升级依据、实际 Diff 和纠正结论；未复核不猜测 |
| 返工 / 回归 | 记录同目标修复轮次、缺陷及关联证据；测试或用户观察缺失时标 `UNKNOWN`，不能把未报告当零 |

历史中断数量、等待与净收益均为 `UNKNOWN`；没有基线不声称已提效。正向目标是在已有有效授权内不新增不必要确认；负向情形仍必须阻断，不能以少问问题掩盖越权。后续 #230 须在两个底座分别覆盖有效 / 过期 / 撤销 / 伪造授权、旧记录补证、含“权限 / 锁 / 迁移”但无语义变化的文字、单行权限变更、遗漏路径、锁冲突、局部阻塞、同一执行者自批及回退；真实 Runtime 未接入的场景标为合成验证。设计本身不证明任何运行时行为。
